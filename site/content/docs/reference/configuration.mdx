<Available>every flag and default below is read from `keyit-cli/src/main.rs`'s `clap` definitions and `keyit-cli/src/init.rs`, verified by running the commands</Available>

This page covers where Keyit's configuration actually lives and how to
override it. For the full file-by-file layout and what's safe to
commit, see [File Formats](/docs/reference/file-formats) — this page
only summarizes the layout before getting to the flags.

## The two places configuration lives

- **`keyit.toml`**, committed at your project root — the project ID,
  label, pinned genesis hash, and **the project's relay URL**, set once
  at `keyit init` and read by every later `push`/`pull`/`invite`/`join`
  in that checkout unless a command's own `--relay-url`/`--relay-dir`
  overrides it for that one call.
- **`.keyit/project.toml`**, under Keyit's data directory (never inside
  your repository) — a redundant, quick-to-read copy of a subset of the
  same project identity, alongside the full signed records and this
  device's local state. See [File Formats](/docs/reference/file-formats#the-local-runtime-cache-keyit)
  for the complete tree.

```toml
# .keyit/project.toml
protocol_version = "keyit/1"
project_id = "kvp_..."
project_label = "my-project"
default_relay_url = "https://relay.keyit.sh"
```

## Setting the relay URL

The relay URL is chosen once, at `keyit init`, and stored as the
project's default:

```sh
keyit init --relay-url https://relay.example.com
```

Omitting `--relay-url` records `https://relay.keyit.sh`, the default
hosted relay. Every subsequent `push`, `pull`,
`invite create`, `join`, `approve`, and `revoke` in this project
resolves its relay the same way: that command's own `--relay-url` (or
`--relay-dir` for a filesystem-backed relay), falling back to the
project's stored default when neither is given. There is no per-command way to force "no relay" once the
project default is an `http(s)` URL — see [Local-only
projects](/docs/reference/file-formats#local-only-projects) if you want
that from the start.

## Environment variables

Keyit reads a small number of environment variables. The two that
matter for everyday use:

- `KEYIT_DATA_DIR` — overrides where the local device key and every
  project's `.keyit/` state live. Mainly for tests and isolated
  walkthroughs; leave it unset to use the real default
  (`$XDG_DATA_HOME/keyit` or `~/.local/share/keyit`).
- `KEYIT_KEY_STORE=file` — forces the local-file key backend even on
  macOS, where the system Keychain is otherwise the default.

## Per-command flags

Every command's full flag list is on the [CLI
reference](/docs/reference/cli) page. In summary, the flags that
override a default rather than specify required input:

| Flag | Commands | Overrides |
| --- | --- | --- |
| `--relay-url <url>` | `init`, `push`, `pull`, `invite create`, `join`, `approve`, `revoke` | The relay this one command talks to (or, on `init`, the project's stored default). |
| `--relay-dir <path>` | `push`, `pull` | Use a filesystem-backed relay directory instead of an HTTP relay for this call. |
| `--project-label <text>` | `init` | Defaults to the project root directory's name when omitted. |
| `--force` | `init`, `pull` | On `init`: overwrite existing Keyit metadata in this directory. On `pull`: replace a local file that has unrecognized changes. |

## Not yet configurable

<ProtocolDefined>
  There is no config file, flag, or environment variable for
  per-environment relay overrides, custom key-derivation parameters, or
  disabling the macOS Keychain backend selection logic (only
  `KEYIT_KEY_STORE=file` forces the fallback explicitly). If you need
  one of these, it isn't a documentation gap — it isn't implemented yet.
</ProtocolDefined>
