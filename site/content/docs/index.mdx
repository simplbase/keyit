Keyit is an open-source, local-first protocol and CLI for securely
synchronizing private project state — starting with `.env`-style files —
across a team's authorized developers and machines.

Its core promise, unchanged since the v1 protocol spec:

```text
Clone the project. Join Keyit. Pull the environment. Start developing.
```

<Available>the CLI, the protocol, and the hosted relay described on this page are all shipped today</Available>

## What Keyit does

A team's private project state — API keys, database URLs, feature
flags, anything that normally lives in `.env.local` — is encrypted on
the developer's own machine, published as a signed revision through an
untrusted relay, and decrypted only by other devices the project owner
has explicitly approved. No plaintext secret value ever has to leave a
device unencrypted, and the relay that carries it never holds the key
that could decrypt it.

Concretely, that means a small set of explicit operations:

- `keyit init` creates a cryptographic project boundary in the current
  repository.
- `keyit env add` registers an environment (`development`, `staging`,
  `production`, or any label you choose) and maps it to a local dotenv
  file.
- `keyit push` encrypts that file's contents and publishes a new signed
  revision.
- `keyit pull` verifies and decrypts the latest revision a device is
  authorized for, and writes it to the mapped local file.
- `keyit invite` / `keyit join` / `keyit approve` bring a new device
  onto the project, gated on explicit approval from an existing Owner
  or Admin.

Every one of those is a real, shipped command — see the
[CLI overview](/docs/reference/cli) for the full reference, generated
from the actual `keyit-cli` argument parser rather than from the
protocol design.

## What Keyit is not

- **Not a password manager.** There's no vault UI, no browser
  extension, no personal credential storage. Keyit moves one team's
  project-scoped environment files between machines.
- **Not a hosted secrets-management SaaS.** The relay that carries
  encrypted revisions is explicitly untrusted — it's a synchronization
  point, not a place secrets are "kept." You can self-host it.
- **Not blockchain-based.** The signed, append-only revision chain
  exists for integrity, provenance, and history — the same reason a
  package registry or a Git repository signs commits. There's no
  mining, no token, and no consensus network involved.
- **Not identity-provider-dependent.** No email verification, no
  OAuth, no third-party identity provider. Authorization belongs to
  cryptographic device identities, approved directly by a project's
  Owner or Admin.

## Project status

Keyit is early software. Project initialization, environment
registration, encrypted push/pull, and the invite → join → approve →
revoke flow are implemented and usable for controlled internal
projects. Keyit has **not** yet undergone an external security audit —
treat it as private beta, and don't rely on it as the only control
protecting high-value production secrets.

Some capabilities are defined in the frozen v1 protocol
spec but not yet exposed by the CLI — most
notably rollback and guided conflict resolution. Pages on this site
mark those explicitly as <ProtocolDefined /> rather than documenting
commands that don't exist yet.
